## Critical Security Pattern: Refresh Token Rotation (Pitfall 2)

When a user calls POST /api/auth/refresh:
1. Verify current refresh token (from cookie)
2. Create new refresh token
3. Store new token hash in database (old token automatically invalid)
4. Return new access token
5. Set NEW refresh token in HttpOnly cookie (browser automatically replaces old one)

This prevents token reuse attacks. Database check in Wave 4 axios interceptor ensures stale tokens are detected.

## HttpOnly Cookie Pattern (Pitfall 3)

Refresh token MUST be:
- Sent in response with `Set-Cookie: refresh_token=...; HttpOnly; Secure; SameSite=Strict; Max-Age=604800`
- HttpOnly flag prevents JavaScript from reading (XSS mitigation)
- Secure flag forces HTTPS in production
- SameSite=Strict prevents CSRF
- Max-Age=604800 = 7 days (matches refresh token expiration)

Access token is NOT sent in a cookie. It's returned in response body, stored in React state by frontend.

## Password Validation

Minimum 6 characters (per requirements). Use express-validator for validation and error response.

## Request/Response Bodies

**POST /api/auth/signup**
- Request: `{ email, password }` (json)
- Response 201: `{ accessToken, user: { id, email, tier } }` (refresh token in HttpOnly cookie)
- Response 400: `{ error: "Email already exists" }` or validation errors
- Response 500: error

**POST /api/auth/login**
- Request: `{ email, password }`
- Response 200: `{ accessToken, user: { id, email, tier } }` (refresh token in HttpOnly cookie)
- Response 401: `{ error: "Invalid email or password" }`

**POST /api/auth/refresh**
- Request: (no body; refresh token from cookie)
- Response 200: `{ accessToken }`
- Response 401: `{ error: "Invalid refresh token" }`

**POST /api/auth/logout**
- Request: (no body)
- Response 200: `{ message: "Logged out" }`

**GET /api/auth/me (protected)**
- Request: Bearer token in Authorization header
- Response 200: `{ id, email, tier }`
- Response 401: `{ error: "Unauthorized" }`

  <action>
    Create `backend/src/middleware/verifyJWT.ts` with middleware to extract and verify Bearer token from Authorization header.
    
    **Requirements:**
    - Extract token from `Authorization: Bearer <token>` header
    - Verify token using jwtService.verifyAccessToken
    - Attach decoded payload to req.user
    - If token missing or invalid: respond 401 `{ error: "Unauthorized" }`
    - If token valid but expired: respond 401 `{ error: "Token expired" }`
    - Continue to next middleware if token valid
    
    **File format:**
    ```typescript
    import type { Request, Response, NextFunction } from 'express'
    import { verifyAccessToken } from '../services/jwtService.js'
    import './../../types/express.js' // Import type augmentation
    
    export async function verifyJWT(req: Request, res: Response, next: NextFunction) {
      const authHeader = req.headers.authorization
      
      if (!authHeader || !authHeader.startsWith('Bearer ')) {
        return res.status(401).json({ error: 'Unauthorized' })
      }
      
      const token = authHeader.substring(7) // Remove "Bearer " prefix
      const payload = await verifyAccessToken(token)
      
      if (!payload) {
        return res.status(401).json({ error: 'Token expired or invalid' })
      }
      
      req.user = payload
      next()
    }
    ```
    
    **Why this pattern:**
    - Middleware checks token presence, verifies signature, and sets req.user
    - Returns 401 early if missing/invalid (cleaner than throw-catch)
    - Next middleware/route can safely access req.user
    - Type augmentation imported so req.user is typed

    **Handler 1: signup(req, res)**

    - Validate email format (use express-validator, or simple regex)
    - Validate password length >= 6
    - Check if email already exists (findUserByEmail)
    - Hash password (hashPassword)
    - Create user (createUser)
    - Create access token (signAccessToken)
    - Create refresh token (signRefreshToken)
    - Hash refresh token for storage (use crypto.createHash('sha256'))
    - Store refresh token hash in database (createRefreshToken)
    - Set HttpOnly cookie with refresh token: `res.cookie('refresh_token', refreshToken, { httpOnly: true, secure: true, sameSite: 'strict', maxAge: 7*24*60*60*1000 })`
    - Return 201 with accessToken and user object (without passwordHash)
    
    **Handler 2: login(req, res)**
    - Extract email, password from req.body
    - Find user by email (findUserByEmail)
    - If not found: return 401
    - Verify password (verifyPassword)
    - If invalid: return 401
    - Create access token
    - Create refresh token, hash, store
    - Set cookie
    - Return 200 with accessToken and user object
    
    **Handler 3: refresh(req, res)**
    - Extract refresh token from req.cookies.refresh_token
    - If missing: return 401
    - Hash the token (same algorithm as signup/login)
    - Find token in database (findRefreshToken with userId from token payload... wait, we need to decode the token first)
    - Actually: Verify token with jwtService.verifyRefreshToken first (this checks signature)
    - Extract userId from decoded token
    - Hash token and query database for matching token with same userId
    - If not found or revoked: return 401
    - Revoke old token (revokeRefreshToken)
    - Create new refresh token
    - Hash and store new token
    - Create new access token
    - Set new cookie with new refresh token
    - Return 200 with new accessToken
    
    **Handler 4: logout(req, res)**
    - Extract refresh token from req.cookies.refresh_token
    - If present: hash and revoke it
    - Clear cookie: `res.clearCookie('refresh_token')`
    - Return 200
    
    **Handler 5: me(req, res) [protected]**
    - Verify req.user exists (middleware ensures this)
    - Query user by req.user.userId (findUserById)
    - Return 200 with user object (id, email, tier)
    - Do NOT return passwordHash
    
    **File format (handlers structure):**
    ```typescript
    import type { Request, Response } from 'express'
    import { createHash } from 'crypto'
    import { hashPassword, verifyPassword } from '../services/passwordService.js'
    import { signAccessToken, signRefreshToken, verifyRefreshToken } from '../services/jwtService.js'
    import { createUser, findUserByEmail, findUserById } from '../services/userService.js'
    import { createRefreshToken, findRefreshToken, revokeRefreshToken } from '../services/refreshTokenService.js'
    
    function hashToken(token: string): string {
      return createHash('sha256').update(token).digest('hex')
    }
    
    export async function signup(req: Request, res: Response) {
      try {
        const { email, password } = req.body
        
        // Validation
        if (!email || !password) {
          return res.status(400).json({ error: 'Email and password required' })
        }
        if (password.length < 6) {
          return res.status(400).json({ error: 'Password must be at least 6 characters' })
        }
        
        // Check existing user
        const existing = await findUserByEmail(email)
        if (existing) {
          return res.status(400).json({ error: 'Email already registered' })
        }
        
        // Hash password and create user
        const passwordHash = await hashPassword(password)
        const user = await createUser(email, passwordHash)
        
        // Create tokens
        const payload = { userId: user.id, email: user.email, tier: user.tier }
        const accessToken = await signAccessToken(payload)
        const refreshToken = await signRefreshToken(payload)
        const tokenHash = hashToken(refreshToken)
        
        // Store refresh token
        const expiresAt = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000)
        await createRefreshToken(user.id, tokenHash, expiresAt)
        
        // Set cookie
        res.cookie('refresh_token', refreshToken, {
          httpOnly: true,
          secure: process.env.NODE_ENV === 'production',
          sameSite: 'strict',
          maxAge: 7 * 24 * 60 * 60 * 1000,
        })
        
        // Return response (without passwordHash)
        return res.status(201).json({
          accessToken,
          user: { id: user.id, email: user.email, tier: user.tier },
        })
      } catch (error) {
        console.error('Signup error:', error)
        return res.status(500).json({ error: 'Signup failed' })
      }
    }
    
    export async function login(req: Request, res: Response) {
      try {
        const { email, password } = req.body
        
        if (!email || !password) {
          return res.status(400).json({ error: 'Email and password required' })
        }
        
        const user = await findUserByEmail(email)
        if (!user) {
          return res.status(401).json({ error: 'Invalid email or password' })
        }
        
        const isValid = await verifyPassword(password, user.passwordHash)
        if (!isValid) {
          return res.status(401).json({ error: 'Invalid email or password' })
        }
        
        // Create tokens
        const payload = { userId: user.id, email: user.email, tier: user.tier }
        const accessToken = await signAccessToken(payload)
        const refreshToken = await signRefreshToken(payload)
        const tokenHash = hashToken(refreshToken)
        
        // Store refresh token
        const expiresAt = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000)
        await createRefreshToken(user.id, tokenHash, expiresAt)
        
        // Set cookie
        res.cookie('refresh_token', refreshToken, {
          httpOnly: true,
          secure: process.env.NODE_ENV === 'production',
          sameSite: 'strict',
          maxAge: 7 * 24 * 60 * 60 * 1000,
        })
        
        return res.status(200).json({
          accessToken,
          user: { id: user.id, email: user.email, tier: user.tier },
        })
      } catch (error) {
        console.error('Login error:', error)
        return res.status(500).json({ error: 'Login failed' })
      }
    }
    
    export async function refresh(req: Request, res: Response) {
      try {
        const refreshToken = req.cookies.refresh_token
        if (!refreshToken) {
          return res.status(401).json({ error: 'Refresh token missing' })
        }
        
        const payload = await verifyRefreshToken(refreshToken)
        if (!payload) {
          return res.status(401).json({ error: 'Invalid refresh token' })
        }
        
        // Check if token is in database and not revoked
        const tokenHash = hashToken(refreshToken)
        const tokenRecord = await findRefreshToken(tokenHash, payload.userId)
        if (!tokenRecord) {
          return res.status(401).json({ error: 'Token revoked or expired' })
        }
        
        // Revoke old token
        await revokeRefreshToken(tokenHash)
        
        // Create new tokens
        const newAccessToken = await signAccessToken(payload)
        const newRefreshToken = await signRefreshToken(payload)
        const newTokenHash = hashToken(newRefreshToken)
        
        // Store new refresh token
        const expiresAt = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000)
        await createRefreshToken(payload.userId, newTokenHash, expiresAt)
        
        // Set new cookie
        res.cookie('refresh_token', newRefreshToken, {
          httpOnly: true,
          secure: process.env.NODE_ENV === 'production',
          sameSite: 'strict',
          maxAge: 7 * 24 * 60 * 60 * 1000,
        })
        
        return res.status(200).json({ accessToken: newAccessToken })
      } catch (error) {
        console.error('Refresh error:', error)
        return res.status(500).json({ error: 'Token refresh failed' })
      }
    }
    
    export async function logout(req: Request, res: Response) {
      try {
        const refreshToken = req.cookies.refresh_token
        if (refreshToken) {
          const tokenHash = hashToken(refreshToken)
          await revokeRefreshToken(tokenHash)
        }
        
        res.clearCookie('refresh_token')
        return res.status(200).json({ message: 'Logged out' })
      } catch (error) {
        console.error('Logout error:', error)
        return res.status(500).json({ error: 'Logout failed' })
      }
    }
    
    export async function me(req: Request, res: Response) {
      try {
        if (!req.user) {
          return res.status(401).json({ error: 'Unauthorized' })
        }
        
        const user = await findUserById(req.user.userId)
        if (!user) {
          return res.status(404).json({ error: 'User not found' })
        }
        
        return res.status(200).json({
          id: user.id,
          email: user.email,
          tier: user.tier,
        })
      } catch (error) {
        console.error('Me error:', error)
        return res.status(500).json({ error: 'Failed to fetch user' })
      }
    }
    ```
    
    **Why this structure:**
    - Token hashing: Refresh token plaintext never stored in database (same as password)
    - Cookie settings: HttpOnly prevents XSS, Secure forces HTTPS in production, SameSite prevents CSRF
    - Password never returned in response (security)
    - Token rotation: Old token revoked before new one issued (Pitfall 2 prevention)
    - Error messages: Generic for login/signup ("Invalid email or password" doesn't reveal if email exists)

|----------|-------------|
| Client → /api/auth | Untrusted email/password; must be validated |
| Middleware → Handler | req.user is trusted (verified by verifyJWT) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-13 | Tampering | Refresh token cookie | mitigate | HttpOnly flag prevents JS from reading; Secure flag forces HTTPS; SameSite=Strict prevents CSRF |
| T-06-14 | Information Disclosure | Access token in response body | mitigate | Token stored in memory only by frontend (Wave 4 enforces); not in localStorage |
| T-06-15 | Tampering | Token rotation replay | mitigate | Old token revoked (revokeRefreshToken) before new token issued; database check prevents reuse |
| T-06-16 | DoS | Password guessing | accept | Rate limiting deferred to Phase 6b; current implementation allows brute force (caveat: bcrypt cost 12 slows attacks) |
| T-06-17 | Elevation of Privilege | Email enumeration | accept | Login response doesn't distinguish between user-not-found and wrong-password (generic "Invalid email or password") |
